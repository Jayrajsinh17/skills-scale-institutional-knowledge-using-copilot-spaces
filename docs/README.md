# OctoAcme Project Management Docs

This folder contains OctoAcme's project management process documentation and serves as an index to help new team members find the right guidance quickly.

## OctoAcme Project Management — At a glance
OctoAcme runs projects iteratively with a customer-first mindset. Core activities:
- Initiation — one-pager, stakeholder alignment, success criteria.
- Planning — backlog creation, estimates, milestone setting, and scope decisions.
- Execution — sprint delivery, PR and QA conventions, and tracking progress.
- Release — release checklists, deployment steps, and rollback plans.
- Retrospectives — capture action items and drive continuous improvement.
- Risk & Communication — identify risks early and keep stakeholders informed.

Roles commonly involved: Product Manager (PM), Product Designer (PdM), Developers, QA, and Stakeholders.

## Where to find templates
Issue and PR templates, plus other templates referenced by these docs, live in the repository’s .github directory (for example: .github/ISSUE_TEMPLATE/).

## How to propose changes
To suggest edits or add new process documents, please use the "Add Content to Project Management Process Docs" issue template:
.github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml

If your change is small (typo, clarification), opening a pull request that updates the relevant file is fine; for larger changes please create an issue first to discuss scope and stakeholders.

## Acceptance & review
Major changes to process docs should be reviewed by the PM and at least one engineering reviewer. Link the PR to the related issue (for example: #2) and request reviews from the relevant stakeholders.
